## 二、R4 产品切片（待逐项授权）

### S1 · Main 最终回复持久化（找回实际交付内容）— **优先**
- **用户任务**：用户交办后，随时能在任务详情/交付件里找回「当时到底交付了什么」——包括 Main 的最终回复原文，而不只是执行层汇报。
- **现状缺口**：`tasks` 详情与 `--out` 交付件的「任务结果」仅是底账持久化的执行层汇报原文；Main 最终回复不落库（P1/P2 §五已登记）。用户无法找回实际交付内容。
- **建议范围**：在交付时持久化 Main 最终回复（schema 演进，版本化迁移；历史任务标记「无存档」，不伪造）；只读路径与导出兼容。
- **验收标准**：
  1. 新任务：详情与 `--out` 交付件均含 Main 最终回复全文（与当次实际发送逐字一致）；
  2. 历史任务：明确标注「该任务无最终回复存档」，不得用执行层汇报冒充；
  3. schema 迁移幂等、旧库可读；`tasks` 读路径保持只读打开（哈希证明）；
  4. 单测 + 三场景端到端（completed/failed/unexecuted）+ E06/E12 回归。
- **授权门**：schema/写语义变更 → owner 批（本片即为批准的切片范围与验收标准）。

### S2 · 任务归属与访问隔离（多用户可信视图）
- **用户任务**：每个用户只看得到自己的任务；本地运维需要全量视图时须显式开启并明示身份边界。
- **现状缺口**：`tasks` 为全 principal 视图（P1 §五.5 已登记为「本地运维视角」）。
- **建议范围**：任务列表/详情按可信 principal 过滤（归属取自渠道事实，同 server 身份路径）；本地运维视图以显式开关（如 `--all`）呈现并标注；不引入新的状态系统。
- **验收标准**：
  1. 双 principal 夹具下互相不可见；详情按 id 访问时校验归属；
  2. 归属来源=可信渠道事实（fake channel 测试证明，不靠模型文本）；
  3. `--all` 仅在显式开启时生效且输出明示「运维视图」；
  4. 既有单 principal 行为与 E06/E12 回归不变。
- **授权门**：多用户部署假设与身份来源确认 → owner 批。
- **限制**：当前无真实平台；用 Dummy + 假渠道夹具验收。

### S3 · P3 语义正名（redo ≠ 人工接管/续跑）
- **用户任务**：产品文案不混淆——`--redo` 是「重新交办」，不是人工接管、不是会话续跑。
- **现状缺口**：P3 报告标题用「人工接管 v1」；README 已加语义边界说明（本轮）。
- **建议范围**：README/decision-log 口径统一；P3 报告首部加一行「名称说明（不改历史证据）」；真续跑（Pi 原生会话恢复）作为独立缺口保留。
- **验收标准**：文档 grep 不再出现把 redo 描述为接管/续跑的表述（历史报告仅加注不改正文）；CLI 帮助与输出文案一致。
- **授权门**：文档级，无需技术授权（列此备案）。

### S4 · 统计口径升级（四态）
- **用户任务**（研发侧）：比较结论必须区分**改善 / 退化 / 证据不足 / 经验证的无实质变化**；`NO_MEANINGFUL_CHANGE` 不得被解读为「已证明无改善」。
- **现状缺口**：`stats.ts` 三态分类把 CI 重叠统称 NO_MEANINGFUL_CHANGE。
- **建议范围**：分类器升级为四态（IMPROVED / REGRESSED / INSUFFICIENT_EVIDENCE / NO_SUBSTANTIAL_CHANGE_VERIFIED）；「经验证无实质变化」需预注册等效界；历史报告不改写，新增口径版本。
- **验收标准**：单测覆盖四态边界（含预注册等效界）；既有 compare 输出标注口径版本；不改写历史报告。
- **授权门**：eval 维护项（owner 已给口径）。

### S5 · 严格盲测流程（holdout 访问控制）
- **用户任务**（研发侧）：正式泛化验收时，实施者对测试内容零访问。
- **现状缺口**：当前 holdout 由复核员生成封存，但非严格盲测（实施者可见目录/清单）。
- **建议范围**：流程约定+路径隔离——holdout 由复核员在实施者不可读路径生成、运行与报告；实施者仅见结论。
- **验收标准**：下次使用 holdout 时按此流程执行并在报告注明；本项不产生产品代码。
- **授权门**：下次 holdout 使用前确认。

## 三、建议实施顺序

`S1`（owner 指定为重要独立切片）→ `S3`（低成本正名，可随任意批次）→ `S2` → `S4`/`S5`（随 eval 使用节奏）。

## 四、边界（不变）

- 真实平台接入 / 写开放 / 发布：owner 分阶段授权；当前一律 Dummy；
- 不新增 Runtime 行为机制、协议字段、状态系统；
- R1 冻结集版本化演进（E01 修复即新版本），历史证据不覆盖；
- 每片交付：用户任务 + 验收标准 + 独立复核 + 可回退提交。
