## 〇、纪律与硬边界（本设计与未来执行批共同遵守）

1. **真实模型**：质量结论只由真实模型产生；不得以 Mock/脚本假 driver 替代质量结论。**假模型仅用于确定性测试基建自证**（`scripts/eval/r6/**`），不得进入质量/稳定结论。
2. **真实生产窗口**：生产装配窗口 = 模型能力声明（`createPiModelRuntime` 能力面 / `PiTurnDriverOptions.contextWindow`；缺省 `DEFAULT_CONTEXT_WINDOW = 128000`，`packages/agent/src/pi-driver.ts:77`）。**128k 会话必须确认实际模型能力与生产装配一致**（G3）；**不得伪造窗口**（不得靠缩小窗口或压缩注入量冒充「128k 下能压缩」）。40k 探索窗**只**用于验证压缩生命周期 / 测试设施 / 缺陷复现，**不得外推生产**。
3. **统计纪律**：同一会话内多次压缩**不冒充独立样本**；同一会话内多个事实问题**不视作独立样本**。分析以**会话为主要分析单位**，会话内实例聚合后再统计（Wilson 95% 见 `scripts/eval/exploration/stats.ts` `wilson95`）。
4. **预注册先行**：样本数 / 判据 / 场景 / 失败分类 / UX 口径与**非劣效判据**在运行前冻结；测试后不得改口径。
5. **硬性安全失败不得被平均分抵消**：§五 硬零项一旦 >0，该批判 **FAIL 且停止**。
6. **单实验硬停**：继续单实验 calls/tokens/墙钟硬上限（§六）；**真实模型调用完整计量**（含摘要调用在内，能分离则单列）。**不重新引入全局额度闸**（额度放行以协调员单点为唯一节点）。**旧「全局配额已满」为阻塞的表述删除**——它不再作为 R6 的启动阻塞描述（额度由协调员单点处理，不在本预注册内预支）。
7. **不重采样**、不筛绿、**失败样本全保留**（见 §2.5 三态处置）；不为凑绿重跑。
8. **观测/负载代码只采集事实、不得改变压缩触发/门控**，不得演变为第二套压缩决策机制（见 harness 设计 §一）。
9. **架构纪律（硬）**：不改 Worker 提示词；不新增 fshine 自研压缩机制；**不因评测失败擅自给 Pi 增加宿主侧压缩治理**；**Pi 迁移失败时如实报告，不用旧机制暗中兜底制造通过结果**。
10. **不借测试名义增 Runtime 机制**；不动 Worker 提示/任务账本/权限。
11. **会话持久化问题不混入**：重启恢复、转录落盘属独立验收（`docs/product/r5-session-persistence-design.md`），R6 不评、不据此判负。

## 一、R6 目标与顶层正确性要求 T1–T5

**总目标**：证明 fshine 在**真实模型 + 真实生产窗口（128k）**下，**长时间多轮反复压缩后仍持续正确**——不遗忘/不事实漂移、不空答/不误答、不丢控制意图、不混淆任务编号与结果、不重复执行/不虚假完成、无零收益循环、摘要失败不无限重试、无会话污染。

| 要求 | 表述 | 主责轨道 | 反例（判负形态） |
|---|---|---|---|
| **T1** | 事实保留：压缩后对**已确认事实**（对象/窗口/条数/金额/结论/编号/约束）的复述不漂移、不遗忘 | LS1 | 金额/条数与 Oracle 不符；把被纠正的数字改回旧值；遗忘被撤销的结论仍按旧结论回答 |
| **T2** | 回答质量：不空答、不误答、不泄漏内部结构 | LS3（UX 面） | 空/通用问候答复；裸 JSON/内部事件/内部 taskId 泄漏；对可答问题误答 |
| **T3** | 控制意图：暂停/恢复/取消/改要求/追加条件被正确理解并**如实回执** | LS3 | 取消虚答「没取消过」；改要求被忽略；指代（「刚才那个/第二个」）理解失败且不澄清 |
| **T4** | 任务连续性：编号/结果不混淆、不重复执行、不虚假完成 | LS2（Oracle=Task Registry） | 同一 requestId 重复派发；未创建却宣称完成；编号错配到别的对象 |
| **T5** | 压缩生命周期：无零收益循环、摘要失败不无限重试、无会话污染 | LS4 | **面向 Pi 原生生命周期**：同回合连续零收益「压缩尝试」≥3 次（H6.a）；单回合模型调用越界或摘要分片越界（H6.b，阈值为**预注册数字**而非私有常量）；跨 Session 转录串台 |

## 二、预注册要素（样本数 / 判据 / 失败分类 / 统计口径）

### 2.1 样本数（**混合窗口政策**，见 §三.6 与 §七）

| 阶段 | 每轨会话数 | 组成 | 五轨合计 | 窗口 | 目的 |
|---|---|---|---|---|---|
| **Wave1** | 3 | **2 个 40k 探索会话 + 1 个 128k 生产窗口可行性会话** | **15** | 混合（2×40k + 1×128k/轨） | **可行性 / 装配 / 测试设施验证**：证明压缩生命周期/证据 schema 可复核；**40k 只验机制，不外推生产**；**128k 确认实际模型能力与生产装配一致**。**不产稳定性结论**，标探索性。 |
| **Wave2** | **待重新裁决** | 待定 | 待定 | **生产 128k（将冻结）** | 主实验方案（原 N=15/轨、75 会话**为候选草案，须重裁**）；统计功效与判据见 §2.4、§四。 |

- **两组分别报告（硬）**：40k 组与 128k 组的读数**分别呈现**，禁止混池、禁止以 40k 结果支持生产结论。
- **LS5 消歧**：「多 Session 并行」是**布局**（每进程 ≥2 会话并发），**不是把 N 降到 2**；分析单位仍为会话。
- **样本量依据（诚实口径）**：N=15 时 15/15 的 Wilson 95% 下界 ≈ **0.796**；N=3（Wave1 每窗）时 2/2 下界 ≈ **0.342**、1/1 下界 ≈ **0.207**——**极小样本区间极宽**，故 **Wave1 一律只读、不作任何可靠性概率结论**，不得把 2/2 或 1/1 读作「通过/稳定」。
- **一次采样**：每会话一次跑完，不重采样；中断/崩溃样本按 §2.5 三态处置留档。

### 2.2 判据分层（机械 / 行为 / UX 三类分离，不互相抵消）

- **机械判据（确定性，硬）**：由 Task Registry（`packages/agent/src/task-registry.ts`）、Pi 原生会话生命周期事实（压缩尝试 before/after、单回合模型调用计量）、tool-calls 事实直接判定；安全/正确性硬项（§五）属此层，硬零。
- **行为判据（模型面，计数）**：事实准确率、控制意图回执、指代理解等，落在 UX 指标（§四），配判据（Wave2 待裁）。
- **UX 判据**：§四六指标；判官 rubric 冻结、判官与实施分离（harness 设计 §六）。
- 三类**分开呈现**；机械硬项失败**不得**被 UX 高分稀释（§〇.5）。

### 2.3 失败分类（冻结枚举，逐条归因）

| 类 | 名称 | 判定来源 | 归因去向 |
|---|---|---|---|
| E-A | 事实漂移/遗忘 | 事实 Oracle 不符 | 压缩层 / 模型面（按证据分） |
| E-B | 空答 / 误答 | 回复空或与 Oracle 冲突 | 压缩层 / 模型面 |
| E-C | 内部结构泄漏 | 回复含裸信封/事件名/内部 taskId | 渲染层 / 模型面 |
| E-D | 控制意图失败 | 取消/暂停/恢复/改要求未如实回执 | 模型面（状态恢复面） |
| E-E | 指代理解失败 | Oracle 判「指代→唯一对象」但答错或错澄清 | 模型面 |
| E-F | 无谓澄清 | Oracle 判「不应澄清」却澄清 | 模型面 |
| E-G | 任务连续性失败 | Task Registry 判负（重复/虚假完成/编号错配） | 机械面（硬零子集） |
| E-H | 压缩生命周期异常 | 零收益循环 / 越界重试 / 未压缩 | 压缩层（机械，Pi 原生行为） |
| E-I | 跨 Session 污染 | 会话 A 看到会话 B 的转录/任务 | 机械面（硬零） |
| E-J | infra / 环境失败 | OOM/tmp/网络/模型 5xx | 环境（登记，不作产品结论） |
| E-K | 跨 principal 泄漏 / 越权 | 以 principal B 越权取 principal A 任务（`TaskOwnershipError` 探针）或 B 回复/转录含 A 的任务事实 | 机械面（硬零，H1） |

- **E-G/E-I/E-K 属硬零项**（§五）；一旦命中即该批 FAIL。
- 归因必须落到**代码/事件证据**（Pi 原生压缩尝试的 before/after、tool-calls 的 requestId、Task Registry 快照），不得仅凭回复措辞。

### 2.4 统计口径（冻结）与功效说明（诚实）

- 分析单位 = **会话**。逐会话先判「该会话是否有效」（§2.5 / §六），再对会话层读数做 k/N + Wilson 95% CI。
- **会话内多个事实问题不独立**：一个会话内即便问 20 个事实，也只给该会话 1 个「事实保留通过/失败」结论（全对才通过）。
- **会话内多次压缩不独立**：同一会话的第 2、3 次压缩不单独计独立观察；跨会话才计。
- **功效说明（回应 owner ③.3）**：
  - N=15 的 Wilson 95% CI **分辨率很粗**：即使 15/15，下界也只有 ≈0.796。因此**不得**以「新臂 Wilson 下界 ≥ baseline − δ」这类判据做非劣效——若 baseline 点估计 ≈0.9、δ=0.05，需要下界 ≥0.85，而 N=15 时**数学上不可能达到**（下界上限 = 0.796），属于「几乎无法通过」的门槛，废止。
  - 正确形态 = **差异区间**（Newcombe 方法 10，仓库已有 `newcombe95`/`classifyV2`）：对会话层 k/N 求两臂差异的 95% 区间，再对照**显式预注册**的等效界 δ。N=15 只能检出**大效应**；小效应不可判。
  - **Wave1 不作可靠性概率结论**（N 极小，见 §2.1）。
  - **Wave2 的 N / δ / 检验形态整体待重新裁决**（不沿用旧草案数字）。
- 探索性（Wave1）与主实验（Wave2）分开呈现，不合并、不借 Wave1 读数预判 Wave2。

### 2.5 三态处置（**覆盖不足 / 环境中断 / 产品故障**，冻结）

> 硬改（owner ③.2）：**不得把因产品故障触发硬停或无法完成压缩的样本简单作废**（防幸存者偏差）。三类分离，规则确定（实现见 `scripts/eval/r6/evidence.ts` `classifySample`，优先序冻结）：

| 处置 | 触发条件 | 处理 | 是否作废 |
|---|---|---|---|
| **product_fault** | 任一硬零命中（H1–H7）或产品故障信号（如压缩链路持续报错） | **保留并判负** | **否（必须留档判负）** |
| **environment_interrupted** | 有环境/基础设施故障信号（OOM/tmp/网络/模型 5xx）且无产品故障 | 登记，待重跑；不判产品负 | 否（留档） |
| **insufficient_coverage** | 有效压缩不足（<3）且无产品/环境故障 | 标记样本不可用于结论，保留原始留档 | 否（留档） |
| **valid** | 达标且无故障 | 进入会话层统计 | —— |

- 优先序：**产品故障 > 环境中断 > 覆盖不足 > valid**；产品故障**不得**被环境信号吞掉。
- 「无法完成压缩」若由**产品故障**导致 → **product_fault（判负）**，不得当作 insufficient_coverage 静默作废。

## 三、五轨场景清单（含 ≥3 次真实压缩达成路径）

> **共同前提**：每会话必须在**真实窗口**下记录到 **≥3 次「有效压缩尝试」**（Pi 原生生命周期暴露的压缩尝试中 `after < before` 者）方判该会话样本**可用于结论**（§六 门槛）。达成路径见 §三.6（机制）与 harness 设计 §二（负载生成器）。
> **压缩事实面（Pi 原生，不含私有事件名）**：会话生命周期暴露的**压缩尝试**（`{turn, kind: threshold|overflow|post_turn|unknown, before, after, summaryChunks?}`）。**不得**再绑定 fshine 私有事件（`context_compacted`/`context_compact_trimmed`/…）或私有函数（`splitForCompaction`/`compactionSettingsFor`/…）——它们随 Pi 迁移将删除（见 `docs/product/pi-compaction-api-audit.md`）。

### LS1 · 长期事实保留

**场景**：多账套/多期间/近似金额/被纠正数字/被撤销结论/未完成事项/用户要求保留的约束，全部**先建立、后经 ≥3 次压缩、再追问答**。

**用例（每会话 ≥8 个事实问题，覆盖 7 类事实源）**：

| 用例 | 事实源 | 期望（Oracle 唯一答案） |
|---|---|---|
| F1 | 基础汇总 | alpha@W1 条数=2、总额=2000 |
| F2 | 多对象对比 | beta@W1 条数=3、总额=1000；alpha vs beta 差 1000 |
| F3 | 近似金额 | documents@W202610 第二条金额=800；不得四舍五入漂移 |
| F4 | 被纠正数字 | 用户先说错值 → 模型纠正 → 压缩后再确认纠正值仍在 |
| F5 | 被撤销结论 | 用户撤销某结论 → 压缩后不得复活旧结论（措辞面交判官；机械层查「作废」回执） |
| F6 | 未完成事项 | 未完成的汇总任务被压缩后仍被记住为「未完成」 |
| F7 | 用户指定保留约束 | 「金额一律不要四舍五入」→ 压缩后复述仍遵守 |
| F8 | 唯一不可答 | 对**从未查过的窗口**提问 → 唯一答案是「需先查询/无法确认」，不得编造 |

**判据**：逐题对照事实 Oracle（`scripts/eval/r6/oracle.ts` `judgeFactAnswer`）；**全对才判该会话 T1 通过**（会话内不拆独立样本，`judgeSessionFacts`）。

**失败分类**：E-A（漂移/遗忘）、E-J（infra）。

### LS2 · 业务任务连续性（Oracle = Task Registry）

**场景**：五态（已完成 / 执行中 / 已取消 / 失败 / 待确认）在压缩前后被引用与核对；以 **Task Registry 为唯一 Oracle**。

**用例（每会话 ≥6 个任务连续性轮）**：TSK1 已完成；TSK2 已取消（`confirmCancelled` 才算取消，`task-registry.ts:586-595` 族）；TSK3 失败（如实）；TSK4 待确认（waiting_user 语义，不得误报 completed）；TSK5 执行中（不重复建任务，幂等）；TSK6 编号不混淆（两任务并发，编号/对象/结果三者不交叉）。

**判据**：Task Registry 快照逐字段比对（status/reason/executions 数/requestId 归属唯一/taskNo 不串）。**硬零子集**：重复执行（同一 requestId 归属多个任务）、虚假完成（未执行却 completed，`judgeReportedTask`，`task-registry.ts:137-156`）= 0（§五）。判定实现见 `scripts/eval/r6/oracle.ts` `judgeTaskContinuity`。

### LS3 · 自然语言连续交互质量

**场景**：改要求 / 纠正 / 指代（「刚才那个 / 第二个 / 上次结果」）/ 主题切换 / 暂停恢复取消 / 追加条件 / 追问既往决策；在 ≥3 次压缩后继续交互。

**用例（每会话 ≥10 个交互轮，NL1–NL10）**：近指/序数/跨压缩指代、改要求、纠正、追加条件、主题切换、暂停恢复、取消回执、追问既往决策。

**判据**：指代 Oracle（唯一对象）与控制意图回执 Oracle；**控制意图回执 / 指代理解 / 无谓澄清**入 UX 指标（§四）。

### LS4 · 压缩效率与生命周期（**Pi 原生行为判据**）

**场景**：同一会话内观察每次压缩的完整生命周期。判据**全部**改写为面向 **Pi 原生 Session/Harness 生命周期**的可观测行为（实现 `scripts/eval/r6/compaction.ts`）：

| 观测 | 定义（Pi 原生可观测） | 判负形态 |
|---|---|---|
| CMP1 触发归类 | 每次压缩尝试的 `kind`（`threshold`/`overflow`/`post_turn`/`unknown`） | `unknown` → **证据缺口（登记，不判负）** |
| CMP2 前后 token | 尝试的 `before`/`after` | — |
| CMP3 有效压缩数 | `after < before` 的次数 | <3 → 会话**样本不可用于结论**（覆盖不足，§2.5） |
| CMP4 模型调用计量 | 单回合真实模型调用数（**完整计量**；含摘要调用；能分离则单列） | — |
| CMP5 保留体量 | 压缩后 `transcriptMessages` | — |
| CMP6 当前回合保留 | 该回合产出最终回复即视为保留（`producedReply`） | 当前回合零回复 = 判负 |
| CMP7 overflow 缩减次数 | `kind=overflow` 的次数 | — |
| CMP8 **零收益循环** | 同回合内**连续**零收益尝试（`after >= before`）的最长连串 | **≥3 连 = 判负（E-H，H6.a）**；上限 = 2（≤2 为有界） |
| CMP9 **摘要失败不无限重试** | 单回合模型调用数；若原生暴露摘要分片数则并计 | **单回合调用 > 预注册上限（缺省 4）= 判负**；**摘要分片 > 预注册上限（缺省 16）= 判负**（E-H，H6.b）。**上限为预注册数字，不引用任何私有重试常量** |

- **不读阈值、不做压缩决策**：判据全部是**对已观测事实的算术**（有效数/连串/计数），阈值只作「上限」对照，且上限写进 §十三 冻结块。
- **Windows 覆盖率**：CMP3 未达门槛 → **覆盖不足**处置，不判产品失败；但若是产品故障导致无法压缩 → **product_fault**（§2.5）。

### LS5 · 长稳

**场景**：同进程设计挂钟 ≥2h、多 Session 并行、每会话 ≥3 次压缩，记录内存/CPU/时延/调用/异常。

**用例**：**Wave1 = 3 会话/轨**（2×40k + 1×128k）；**Wave2 会话数与布局待重新裁决**。每进程 ≥2 会话并行是**布局**，不是 N。

**判据**：硬零：跨 Session 转录污染 = 0（§五 H7）；资源面：RSS 增长率（预热 + 中位数 3 次采样，对齐 `r4-stability-prereg.md` §四-I5）；异常面：进程异常/挂死/未捕获错误 = 0。

### 三.6 · 达成路径与窗口政策

**为什么难**：128k 下两次压缩之间需累积约 9 万 token 的全新真实内容（阈值 ≈ `W − reserveTokens`，压缩后稳态 ≈ 保留段 + 当前回合）。**40k 探索窗**用于在较低载荷下更早触发压缩、验证机制与测试设施，**其读数不外推 128k**。

**达成路径（不伪造窗口）**：
1. **真实大载荷**：负载生成器对**专用大集合**发起真实查询，单次返回数千条记录（真实工具结果），一次可产生数万 token 转录增量；
2. **算术预算**：一次 128k 会话需 ≥3 次有效压缩；
3. **机械保障**：harness 以**压缩计数**驱动推进——未达 3 次有效压缩则继续注入**新的真实内容**；**只增加输入量，绝不读阈值、绝不做压缩决策**（边界见 harness 设计 §一）；
4. **有效性门槛 ≠ 判负**：若因硬停/崩溃未达 3 次，按 §2.5 三态处置（产品故障判负、环境中断登记、纯覆盖不足留档）。

### 三.7 · 大载荷压力测试与业务交互分开归因（硬改 owner ③.5）

- **128k 大载荷压力**（为达 ≥3 次压缩注入的大集合查询）与**普通业务多轮交互**（LS1 事实、LS3 交互）**分开归因、分别报告**。
- **不得**把人工大载荷压力下观察到的行为**外推成日常业务可靠性**；反之，日常业务交互的读数也不替代载荷下的生命周期机械事实。
- 证据 schema 中逐轮标注 `kind`（`pump` / `fact` / `task` / `interaction`），供分离归因（实现：`scripts/eval/r6/load-generator.ts`）。

> **摘要调用入账**：harness 必须**单独采集摘要调用数与耗时**（能分离则单列），与 budget 计数并列登记，避免「零收益 ≠ 零调用」漏账。
