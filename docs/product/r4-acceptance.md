## 一、口径与分层

- **两层分流**（每条用例必须标层级）：
  - **确定性（T）**：Runtime 状态机、并发、故障注入、权限、归属、拒绝路径、只读/转义/幂等哈希——用仓内 dummy 夹具 + 假渠道/假 driver，零模型；通过门槛 = **全过**（逐条精确断言，不允许放宽）。
  - **真实 Pi 黑盒（E）**：多轮理解、任务引用、交互质量、业务结果——真实模型 + 仓内 dummy 执行层（与 `npm run ask` 同源装配）；按 §五 预注册 N/Wilson 95% CI 口径报告，不作「全过=稳定」结论。
- **安全不变量一律确定性验证**（不进入黑盒）：任务归属/越权拒绝（`TaskOwnershipError` 语义）、执行子进程凭据白名单（PATH/HOME/TMPDIR）、只读 operation 允许集合的发起前拒绝、ops/渠道文本转义、只读路径哈希不变。黑盒用例不得成为这些不变量的唯一证据。
- **用例字段（每条五要素 + 层级）**：`用例 ID` / `层级` / `输入` / `预期输出` / `状态转换` / `执行证据` / `失败判据`。
- **证据格式**：确定性用例——测试文件路径 + 命令 + 退出码 + 关键断言输出；黑盒用例——run-dir（复用 convergence-r1 runner 证据 schema：`inputs/model/toolcalls/transcripts/audit+index/executions/reply/meta/state/db/judgment`，`runner.ts:479-539`）+ 判定摘要。
- **成本与纪律**：确定性用例零模型；黑盒用例按预注册 N 采样，禁止重采样至绿、禁止单次 PASS 宣称稳定、禁止用 mock 冒充真实 Pi 成功（任务书核心约束）。

## 三、ask 自动回放设计（脚本格式 + 五场景）

### 3.1 脚本格式（设计）

```yaml
scenario: R-A            # 场景 ID
session: { principal: <id>, session: <id> }   # 可信身份（渠道事实或显式参数；不接受模型声明）
config: <path>           # runtime 限额/夹具配置（确定性场景用小额度）
turns:                   # 消息序列（逐条 send；可指定上游等待/注入点）
  - { kind: message, text: "…" }
  - { kind: inject, event: task_completed, taskNo: 1 }   # 确定性注入（假 driver/假通知）
  - { kind: restart }    # 进程重启（分段执行）
expect:                  # 期望断言（自动判定）
  - { after: 1, assert: reply_contains, value: "#1" }
  - { after: 2, assert: main_not_blocked, maxMs: 15000 }
  - { after: all, assert: no_fabricated_numbers }
evidence: [replies, executions, notifications, task_rows, audit]
threshold: deterministic # 全过；黑盒项另列 N/CI（§五）
```
- 复用：runner 证据 schema（`runner.ts:479-539`）、`--suite` 接缝（`suite-contract.ts:1-16`）、假渠道装置（`server.test.ts`）、dummy 夹具故障场景、safety-gate（`safety-gate.ts:88-159`）；**不另建框架**（回放器=共享装配 + 记录包装器的最小 CLI）。
- 断言类型（最小集）：`reply_contains/reply_not_contains`、`task_state`（状态迁移）、`task_no`（数字 ID 稳定/不复用）、`execution_count`、`notification_delivered`（去重/attempts）、`not_blocked`（时延上限）、`resource_released`（活跃 worker/等待计数）、`hash_unchanged`（只读）、`no_fabricated`（数值/对象锚点，复用 convergence-r1 判定口径时只读引用其判据文件）。
- 黑盒断言（真实模型层）与确定性断言分层标注；同一脚本先跑确定性层（假 driver），再跑黑盒层（真实 Pi + dummy）。

### 3.2 场景 R-A：后台任务与前台聊天并行（§7-3、§8-1/3/11）

- **输入序列**：t1「交办耗时查询（后台执行）」→ t2（执行中）「同时帮我看另一件事」→ t3「刚才那个任务怎么样了？」；注入点：t2 到达时后台任务处于 running（假 driver 挂起或真实慢查询）。
- **断言**：t1 快速受理：回复含数字 ID + 业务名（受理时延上限，不含执行结果）；t2 在后台运行中即获得独立回复（Main 不假死，时延上限）；t3 返回状态事实（进行中/完成/失败，来自底账）；后台完成通知可被 Main 读取（按 §决策问题 5 裁定形态）。
- **证据**：回放 run-dir（replies/executions/notifications/task_rows/audit）+ 受理/响应时延记录。
- **失败判据**：前台被后台阻塞（t2 超时/无回复）；t1 无数字 ID/业务名；t3 状态编造或与实际不符；后台完成通知缺失。
- **层级**：受理时延/状态一致性=确定性；自然语言理解与回复质量=黑盒。
- **§对应**：§7-3；§8-1（数字 ID/业务名）、§8-3（不假死）、§8-11（前台可用）。

### 3.3 场景 R-B：主动通知（§7-4、§8-4/7/8）

- **输入序列**：t1 交办任务 →（无追问）→ 注入/等待完成 → t2「结果给我」。
- **断言**：阶段进展通知与终态通知按状态变化生成（受理/开始/里程碑/等待/完成/失败/取消/超时/资源限制）；`(task_id, kind, state_version)` 去重；投递失败有 attempts 记录且可见；终态通知不静默丢失（可节流）；通知文本基于真实事实（无编造百分比/重试/原因）、业务语言、可带 Request ID；t2 能取回结果摘要与交付物。
- **证据**：notifications 表快照 + 假渠道投递记录 + tasks/ops 页面/命令输出。
- **失败判据**：通知缺失/重复/含编造字段；投递失败不可见；结果不可找回。
- **层级**：写点/去重/重试/字段来源=确定性；通知可读性/语言质量=黑盒。
- **§对应**：§7-4；§8-4、§8-7、§8-8。

### 3.4 场景 R-C：挂起接续（§7-1/3、§8-5/6）

- **输入序列**：t1 交办存在歧义的查询 → 执行层 `needs_input`（候选）→ Main 提问并进入 waiting_user →（断言资源释放）→ t2 用代词/省略作答 → 恢复执行 → 完成。
- **断言**：任务进入 `waiting_user` 且持久化 `pendingQuestion`（缺失项/候选原样）；挂起期间无活跃 worker/模型资源（资源计数归零）；答复后**同一 Task** 继续（task_no 不变、executions 追加、不新开任务）；代词/省略由 Pi 原生上下文理解（证据中无规则式消解器痕迹——Runtime 只做确定性身份/状态/权限）；等待超时到期后关闭活跃等待但保留历史（状态与原因机械落库）。
- **证据**：task_rows 前后快照、资源计数、replies、executions、等待超时注入记录。
- **失败判据**：挂起仍占资源；答复产生重复副作用或新任务取代；状态不恢复/不落库；Runtime 出现规则消解实现。
- **层级**：状态/资源/归属=确定性；代词理解与追问质量=黑盒。
- **§对应**：§7-1、§7-3；§8-5、§8-6。

### 3.5 场景 R-D：重启（§7-2、§8-10）

- **输入序列**：启动后台任务 → 中途 `restart`（进程终止/重启）→ 新进程查询任务与通知 →（按裁定）继续/标记。
- **断言**：任务状态与通知在重启后可恢复；已完成任务不重跑；无 `lease` 的 running 行处置按 owner 裁定（重新入队或标记 unknown，不得静默丢弃）；**不重放副作用**（completed 的疑似调用零新增）；等待用户的历史保留。
- **证据**：重启前后底账/通知快照、两段进程日志、执行审计行计数（字节级比对）。
- **失败判据**：重复执行已完成副作用；状态/通知丢失；running 行被静默重写为成功。
- **层级**：确定性（幂等/lease/不重放）；无模型调用。
- **§对应**：§7-2；§8-10（重启）。

### 3.6 场景 R-E：资源限制（§7-6、§8-2/11）

- **输入序列**：小额度配置（并发 1/队列容量 1/预算小/深度 1）→ 连续交办 N+1 个任务 → 触发队列满/预算耗尽/深度超限 → 前台再发一条确定性查询。
- **断言**：超限路径确定性拒绝或受控排队（按配置语义，错误码/话术固定）；无无限积压；拒绝不损坏已入队任务；预算耗尽时子 Worker 共享父预算且不静默继续；前台配额独立、满载仍可确定性查询（不永久阻塞）。
- **证据**：配置、拒绝输出/错误码、队列长度与状态、前台响应时延、预算计数。
- **失败判据**：无限积压/进程崩溃/静默丢弃/前台被阻塞/预算被复制放大。
- **层级**：确定性（拒绝路径/并发/预算）；错误话术的用户可读性=黑盒（可选）。
- **§对应**：§7-6；§8-2、§8-11。

### P1 底账演化：数字 ID + 业务名称 + S1 回复存档

- **P1-T01 迁移幂等与回填**｜确定性｜输入：旧库副本（含历史任务）+ 迁移两次｜预期输出：列/表存在；历史行 `task_no` 按 `created_at` 有序回填且唯一；历史行 `reply_text` 为 NULL（显示「无最终回复存档」）；旧行其余字段逐字节不变｜状态转换：无｜证据：迁移前后行快照 diff｜失败判据：重复迁移产生差异/编号重复/历史被改写。
- **P1-T02 并发分配与不复用**｜确定性｜输入：多连接并发 `begin` N 次（含跨进程）｜预期输出：数字 ID 唯一、连续（按分配序）、失败不占号；不复用/不回退｜状态转换：accepted｜证据：插入结果 + 并发失败注入｜失败判据：重复号/跳号不可解释/竞态崩溃。
- **P1-T03 数字 ID 与业务名展示**｜确定性｜输入：ask/tasks 列表/详情/--out/ops 各一次｜预期输出：均含 `#<no>` 与业务名（业务名为模型提供或机械回落，按决策问题 4 裁定）；UUID 不出现在业务展示位（仅内部关联/证据）｜状态转换：无｜证据：各命令输出金样｜失败判据：缺数字 ID/名称、或以 UUID 充当业务 ID。
- **P1-T04 Main 回复存档（S1）**｜确定性 + 黑盒｜输入：completed / failed / unexecuted 三场景各一轮｜预期输出：详情与 `--out` 含 Main 最终回复全文，与当次实际发送逐字一致（SHA 比对）；历史任务明确标注「该任务无最终回复存档」，不以执行层汇报冒充｜状态转换：running→终态后回复可见｜证据：任务行快照 + 输出逐字比对｜失败判据：回复缺失/不一致/历史任务用汇报冒充。
- **P1-T05 只读路径哈希不变**｜确定性｜输入：列表/详情/--out 前后主库哈希｜预期输出：哈希不变、不建库、不写库｜失败判据：哈希变化或新文件。
- **P1-E01 回复逐字（黑盒）**｜黑盒｜输入：真实模型 ask 一轮（预注册 N）｜预期输出：k/N 报告 + Wilson 95% CI；回复与存档逐字一致的成功率（CI 口径）｜证据：run-dir + judgment｜失败判据：确定性不变量失败；统计层面按 CI 表述，不作全过结论。

### P2 任务生命周期状态机

- **P2-T01 状态转移矩阵**｜确定性｜输入：按任务书 §4 状态集构造转移（accepted/queued→running→completed/failed；needs_input→waiting_user；取消请求→canceling→canceled；超时→timed_out/human 标记）｜预期输出：仅允许的转移成功，非法转移确定性拒绝；每次转移机械落库（时间戳/原因）｜状态转换：见输入｜证据：转移表测试 + 行快照｜失败判据：非法转移被接受/状态丢失/原因编造。
- **P2-T02 等待用户与接续**｜确定性｜输入：执行层 `needs_input`（含 missing/candidates）→ 用户答复（含代词/省略）｜预期输出：任务 `waiting_user` + `pendingQuestion` 原样持久化；答复后同一 Task 继续（task_no 不变、executions 追加、不判 failed）｜状态转换：running→waiting_user→running→completed｜证据：task_rows 快照 + executions｜失败判据：直接判 failed/新开任务/候选被改写。
- **P2-T03 取消请求与确认**｜确定性｜输入：越权取消（换 principal/session）+ 合法取消（排队中/运行中）｜预期输出：越权=TaskOwnershipError（不存在同错误）；合法取消先 `canceling`、确认中止后 `canceled`；取消不重放已发生调用｜状态转换：queued/running→canceling→canceled｜证据：错误输出 + 状态行 + 审计行计数｜失败判据：取消请求被当成已取消/越权成功/取消引发重复执行。
- **P2-T04 超时**｜确定性｜输入：排队等待超时、执行超时（假 driver 挂起）｜预期输出：`timed_out` + 机械 failureReason；不重放；等待超时关闭活跃等待但保留历史｜证据：状态行 + 计时断言｜失败判据：状态错/原因编造/重放。
- **P2-T05 展示词表**｜确定性｜输入：新状态在 tasks/ops 显示｜预期输出：中文词与原因行金样；未知状态 fail-open 显示原值｜失败判据：词表漂移/崩溃。
- **P2-E01 E05/E06 行为回归（黑盒）**｜黑盒｜输入：冻结用例 E05/E06（判据/用例零改动，仅运行，预注册 N）｜预期输出：k/N + CI，与既有帧可比性标注；任何判负逐条归因｜失败判据：判据被改/样本被筛。

### P3 S2 任务访问隔离

- **P3-T01 双 principal 互不可见**｜确定性（安全不变量）｜输入：双 principal 夹具（各自任务）｜预期输出：list 只含自身；detail 越权取 id 返回同一「不存在或不属于」错误（不泄漏存在性）｜证据：命令输出 + 错误文案｜失败判据：跨 principal 可见/错误区分存在性。
- **P3-T02 运维视图 --all**｜确定性｜输入：缺省 vs `--all`（身份来源按决策问题 9 裁定）｜预期输出：缺省按可信 principal 过滤；`--all` 仅显式开启且输出明示「运维视图」｜失败判据：缺省泄漏全量/`--all` 无标注。
- **P3-T03 单 principal 既有行为**｜确定性｜输入：单 principal 列表/详情金样｜预期输出：与现行为逐字一致｜失败判据：回归漂移。
- **P3-E01 E06/E12 回归（黑盒）**｜黑盒｜输入：E06/E12 预注册 N｜预期输出：k/N + CI 与帧口径标注｜失败判据：同 P2-E01。

### P4 通知 outbox

- **P4-T01 写点与去重**｜确定性｜输入：状态转移序列（受理/开始/里程碑/等待/恢复/完成/失败/取消/超时/资源限制）｜预期输出：每状态变化一条通知；`(task_id, kind, state_version)` 唯一；重复触发不新增｜证据：notifications 行快照｜失败判据：缺失/重复/串行错乱。
- **P4-T02 重试与失败可见**｜确定性｜输入：假发送器连续失败→恢复｜预期输出：attempts 递增、退避有界、成功写 `delivered_at`、超上限后停止且未送达在 tasks/ops 可见｜失败判据：无限重试/静默吞失败/重复送达。
- **P4-T03 终态不静默丢失**｜确定性｜输入：终态（完成/失败/取消/超时/等待）各一｜预期输出：终态与用户动作类通知必达或显式失败可见（可节流但不得吞）｜失败判据：终态通知消失。
- **P4-T04 事实性与语言**｜确定性（字段来源）+ 黑盒（语言）｜输入：完成/失败/取消通知｜预期输出：字段来自底账（无编造百分比/重试/原因）；业务语言可读；Request ID 仅追溯｜失败判据：通知含编造或内部路径/凭据。
- **P4-T05 Main 可读历史**｜确定性（按决策问题 5 裁定形态）｜输入：未送达/已送达通知 + 下一回合｜预期输出：按裁定（注入 or 只读工具读取）行为确定且去重；若裁定未定，本条标记 blocked-by-decision 不实施｜失败判据：不可读/重复读/语义层注入越界。
- **P4-E01 后台完成通知（黑盒）**｜黑盒｜输入：后台任务→完成→通知（预注册 N）｜预期输出：通知送达率 k/N + CI；内容与事实一致率｜失败判据：确定性不变量失败。

### P5 资源强制

- **P5-T01 单一配置**｜确定性｜输入：新 `runtime` 段（含非法值）+ grep 守卫｜预期输出：非法 fail-fast；生产代码无第二配置源（host.* 处置后无残留双源）｜失败判据：静默回落/双源。
- **P5-T02 同会话串行**｜确定性｜输入：同会话两条消息并发（重现审计竞态：`execution-runtime.ts:192/261/278` 共享状态）｜预期输出：串行处理；转录不互相覆盖；两条回复都可追溯｜失败判据：转录丢失/交错回复。
- **P5-T03 队列与配额**｜确定性｜输入：队列容量满载 + 前台配额独立｜预期输出：满=确定性拒绝（错误码/话术固定）或受控排队；前台不被后台永久阻塞｜失败判据：无限积压/前台阻塞。
- **P5-T04 委派深度**｜确定性｜输入：depth 超限委派｜预期输出：确定性拒绝；不产生半成品任务｜失败判据：越限执行。
- **P5-T05 父预算共享**｜确定性｜输入：父任务带预算 + 子 Worker 委派（假 driver 计费）｜预期输出：子不复制预算；耗尽→确定性失败/终止并落库原因｜失败判据：预算放大/静默超支。
- **P5-T06 等待超时**｜确定性｜输入：waitUserTimeout 到期｜预期输出：关闭活跃等待、保留历史与原因｜失败判据：状态丢失/资源不释放。
- **P5-E01 顺序行为不回归（黑盒）**｜黑盒｜输入：现有 ask 场景（预注册 N）｜预期输出：结果分布与基线帧可比性说明｜失败判据：产品行为回退到不可用。

### P6 后台任务执行

- **P6-T01 调度与不绑 Agent**｜确定性｜输入：假 driver + 假底账调度 N 个任务｜预期输出：queued→running→completed/failed/取消/超时；每次委派新建 Worker 回合，无长驻 Agent 对象｜失败判据：状态卡死/重复执行。
- **P6-T02 转录隔离**｜确定性｜输入：后台执行中/后检查 Main transcript｜预期输出：后台内容不进 `mainMessages`；Main 回合转录仅含自身消息｜失败判据：串写/泄漏。
- **P6-T03 重启恢复与不重放**｜确定性｜输入：重启（含 lease 过期注入）｜预期输出：queued 恢复、已完成不重跑、无副作用重放；running 处置按裁定（不得静默改成功）｜失败判据：重放/丢失/静默改写。
- **P6-T04 后台并发上限**｜确定性｜输入：backgroundConcurrency=N 下提交 N+1｜预期输出：第 N+1 排队或拒绝（按配置）｜失败判据：超并发执行。
- **P6-T05 前台可用**｜确定性｜输入：后台满载 + 前台确定性查询｜预期输出：前台在配额内即时可用（时延上限）｜失败判据：前台被占满阻塞。
- **P6-E01 后台任务端到端（黑盒）**｜黑盒｜输入：交办→后台执行→完成→通知（预注册 N）｜预期输出：k/N + CI；通知与结果可取回｜失败判据：确定性不变量失败。

### P7 ask-first 扩展

- **P7-T02 脚本化回放**｜确定性｜输入：回放脚本（§3.1 格式；含坏脚本/多 session/多 principal）｜预期输出：合法脚本可重复执行且逐字可复现（假 driver）；坏脚本 fail-closed exit 2；不加载探索根之外脚本｜失败判据：静默降级/越界加载。
- **P7-T03 结构化轨迹 + 自动断言**｜确定性｜输入：`--trace` 回放｜预期输出：11 类证据齐全（与 runner schema 一致）；断言引擎输出 pass/fail 与失败定位｜失败判据：证据缺项/断言误报漏报。

- **P7-E01 交互式 3 回合（黑盒）**｜黑盒｜输入：3 回合真实模型会话｜预期输出：逐回合证据留档（N=3 仅作 smoke 证据，按预注册表标注不构成稳定性结论）｜失败判据：会话中断/确定性不变量失败。
