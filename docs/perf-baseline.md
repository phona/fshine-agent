# 性能基线（perf:suite / perf:report）

状态：**工具已归档，基线取自 2026-10-16**。两个入口：

- `npm run perf:suite`——全量套件连跑 3 轮，日志落 `.runtime/perf/suite-r*.log`，报告每轮 wall 与红绿。用途：flake 背书、改测试基建前后的耗时对比。
- `npm run perf:report`——出一张两段式报告：A 段解析套件日志（按功能模块/文件/稳定性），B 段解析 `.runtime` 探针 json（真实链路每轮延迟）。纯只读。

## 读数前提（先立规矩再读数）

1. **测试耗时分布 ≠ 系统运行热点**。套件里有真实时钟用例和真 spawn CLI 的保真设计，A 段的头部（handler.test 42.8%）是测试写法，不是系统慢点。
2. **B 段是 mock 执行器口径**：真实平台执行段（浏览器操作）未计入。真平台接入后数字要重采。
3. 系统延迟由模型侧主导（详见下），宿主机械 <3%——**任何宿主侧微优化都不会被这两张表感知到**。

## 2026-10-16 基线

### 套件（3 轮全绿，零 flake）

- 墙钟 59.0–60.0s；内部 = 并行测试 ~123.6s + 收集 ~40s（30 个 e2e 文件各自模块顶层 spawn CLI 派生四张表的固定成本）+ 准备 3.9s。
- 串行口径 123.4s：单测 70.2s（56.9%）/ e2e 53.2s（43.1%）；e2e 单例均重 ~403ms，是单测（59ms）的 ~7 倍。
- 关键路径 = `apps/server/handler.test.ts` 单文件 52.9s（真实 sleep 用例），墙钟下限由它决定。
- 轮间极差最大 66ms——秒级以上才当 flake 查。

### 真实链路（10-16 标定批：3 轮 × 7 场景 45 轮，真 LLM + mock 执行器）

- 每轮：p50 **51.7s**，p90 146s，max 480s。场景梯度：闲聊 15.7s << 单步委派 35–55s << 错误态重规划 103.9s。
- 成本模型：纯对话基座 ~20.8s；**委派边界 +31s**（worker 会话的模型轮次）；同一委派内第二次平台调用仅 +2s（CLI spawn + 机械）。
- 长会话不衰减：5 个 ≥12 轮实例组内对照全部"末 5 轮 ≤ 前 5 轮"——上下文装配的压缩/裁剪有效，20 轮后没有变慢曲线。
- 离散度是主特征：B1 同题 85 轮 6s–194s（32 倍），耗时与回复长度相关仅 0.15——时间花在模型思考/工具轮次深度，宿主无从优化。
- 尾部来自纠错/多步的重规划循环；实测尾部 8.5min vs worker 超时 15min，余量 1.7 倍（真平台接入后最先重看的数字）。

## 改动纪律

- 涉及提示词/申报/澄清的改动照旧走 change-safety F6 探针基线；`perf:report` 只做性能侧的前后对比，不设硬门（样本量小，看轨迹不卡单点）。
- 真平台接入时：重采 B 段 + 重估 worker 超时与单任务墙钟预算（估时声明进计划门的那条契约位就是为此留的）。
