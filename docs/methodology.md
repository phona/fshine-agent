# 方法论：不确定性治理与经验沉淀（methodology）

状态：**作业纪律与设计判据**。来源：2026-10-18~19 薪酬域全链诊断与 A2A 协议落地的实战复盘。
本文管"怎么工作、怎么判断"；机械约束在 architecture-laws.md，协议在 a2a-protocol.md，
改动防线在 change-safety.md，未清偿事项在 debt-ledger.md——四者引用本文判据编号，不重复正文。

## 一、诊断纪律（与不确定性 battle 的作业流程）

系统行为与预期不符时，按序作业，禁止跳步：

1. **审计先行**：先读 tool_calls / worker_messages / delegation_span 还原完整时间线，再谈假设。
   本轮全部根因（门三支、execution 判据、SSE 误判）均出自审计回放，无一来自推测。
2. **字节按字段归因**：任何"流量/体积巨大"的结论必须拆到字段级再下。
   实测教训：552KB 流里 reasoning 只占 1.9KB，其余是 SSE usage/id 回显——按总量推断即误判
   （"marathon 思考"错误结论由此而来）。
3. **形态检验**：每条协议规则问"违反会被代码拦住吗？"——拦得住=机制，拦不住=散文；
   散文必然漂移（planNotice 四段散文与门语义打架的教训）。修复=升格为机制或删除。
4. **单点溯源**：一个现象多种解释时，找能唯一解释它的那一行判据
   （run6：execution() 只数网关调用一行，唯一解释了纯本地任务诚实报告被顶掉）。
5. **变体实测**：格式适应性的直觉必须用变体文件实测（改列名/新列/空表/坏文件/全新模板），
   每个变体暴露的缺陷固化为回归用例（test/test-detect.py），不许只靠真实附件手工验证。
6. **跨运行收敛**：正确性验收至少两次独立运行数值收敛；单次成功不作数。

## 二、设计判据（编号供引用，细则见对应文件）

1. **执行痕迹**：任何被放行执行的调用都构成执行证据，与形态无关（网关/local/非网关直跑）。
   纯本地任务的"零网关调用"不是零执行（run6 实测教训）。
2. **计划语义声明制**：read/write 需激活计划，scratch 直调；声明归执行层（accessSemantics 下发），
   执法归宿主；未登记形态 fail-closed。
3. **假绿灯红线**：无法识别的输入 → NEEDS_INPUT 对齐工单，绝不静默报"满足契约"。
4. **报告三级**：BLOCKING（先问再做，不出产物）/ CONFIRM（可产出，报告开头列默认待确认）/
   NOTE（仅标注）。影响交付范围或金额实质且无默认规则 = BLOCKING。
5. **报告来源归因**：数据来源按文件归因；样本产物不得使用真实交付物命名。
6. **毕业四条件**：结果被验收 / 逻辑可确定性复述 / 重复性可预期 / 边界已收口——四条全绿
   才能从临时脚本毕业为 operation；毕业产物三件：mapping、规则代码、清单条目。
7. **双回路**：运行回路（已知形状：脚本执行+例外裁决）与学习回路（新形状：探索+对齐）；
   学习回路的每次对齐沉淀回运行回路——探索的投资不复利归零。
8. **职责分界**：认证归宿主；实体授权归执行层；语义表声明归执行层、执法归宿主；
   模型上下文只装协议义务+委派块+判断切片，永不装数据总线。

## 三、已登记的接受项（授信期，沙箱阶段收口）

- 非网关 bash 可触达部署凭据路径（提示注入外泄面）
- 溢出快照目录部署级共享（跨任务 hash 不可猜）
- 供应商吞吐与时延方差——收尾+续跑机制兜底；P5 后生成量下降进一步收窄

- 新域接入按「二、6 双回路」与 a2a-protocol 生命周期对照
