# 企微端手工测试用例（幻晟记账助手）

> 目的：补齐自动化测不到的部分——真实企微收发、人眼判断回答质量。
> 前提：后台 server 已运行（真实 MCP 模式）。17dz 为**活账套**，凭证金额可能随时被真实会计修改，
> 预期结果只锚定稳定要素（账套名/期间/凭证号），金额以"给出具体数字且前后一致"为准。

## 0. 前置检查

| 项 | 方法 | 通过标准 |
|---|---|---|
| server 存活 | `ps aux \| grep apps/server/main.ts` | 进程存在；`tail /tmp/fshine-server.log` 末尾有 `server_started` 且 `fakeMcp:false` |
| 企微连接 | 日志中有 `Authentication successful`、`Heartbeat timer started` | 无重连风暴 |
| 机器人单连接 | 测试期间不要跑 `npm run smoke:wecom` | 会互踢 |

- 授权账号：配置里 `wecom:woyEfz...` 对应的企微账号（下称"主账号"），授权账套仅 1 个。
- 会话 TTL：5 分钟。同一账号+会话的消息共享状态；换企微的会话窗口=新状态。
- 同一会话消息**串行处理**：连发会排队，属正常。

## 1. 冒烟：基础链路（P0）

| # | 操作 | 预期 |
|---|---|---|
| 1.1 | 主账号发送：`查一下幻晟本期的凭证` | 回复含：账套全称「幻州市幻晟财务代理有限公司」、期间 202608、凭证张数（当前 15 张）、记-00X 凭证内容；**不应**出现"查询失败/请稍后再试" |
| 1.2 | 接 1.1，发送：`下一页` | 二选一均通过：①返回后续凭证（说明有游标）②如实告知"已全部展示，无更多分页"。**不得**出现编造的新凭证号 |
| 1.3 | 接 1.1，发送：`刚才查的是哪个账套？` | 准确答出「幻州市幻晟财务代理有限公司 / as_001」 |
| 1.4 | 换一个**未授权**的企微账号发送：`查一下幻晟的凭证` | 回复"该账号未开通查询权限"，无任何数据 |

## 2. 多轮会话与状态（P0）

| # | 操作 | 预期 |
|---|---|---|
| 2.1 | 发送模糊查询：`查一下凭证` | 要么列出候选账套让你选（回复 1 即选定），要么直接按唯一授权账套回答；不应答非所问 |
| 2.2 | 接 2.1 若出现候选，改发：`算了，先看看现在几月份` | 应答出当前期间 202608（话题切换不被旧候选卡死） |
| 2.3 | 连发两条（间隔 1~2 秒）：`查一下幻晟本期的凭证` + `我上一条消息问的是什么？` | 两条都有回复（排队串行）；第二条准确复述第一条 |
| 2.4 | 发送：`先别管凭证了，系统登录状态正不正常？` | 答登录正常（loggedIn true），不出现"查询失败" |
| 2.5 | 等待 6 分钟后发送：`刚才查的账套叫什么？` | 会话过期后应正常重新查询（可要求你重述账套名），不报错、不串账套 |

## 3. 专业问答深度（P1）

> 会计视角的真实问法。金额是活的，验证"有具体数字、且多次回答一致"。

| # | 操作 | 预期 |
|---|---|---|
| 3.1 | `幻晟8月份账做到哪了？` | 给出期间 + 凭证张数 + 已展示凭证的日期（如 08-31）；若返回截断，应**如实说明**而非编造"最后一张" |
| 3.2 | `这个月有没有涉及税金的凭证？` | 基于真实凭证回答（当前记-001 含销项税额 298.01）；引用科目/金额应与凭证一致 |
| 3.3 | `管理费用这个月记了哪些开支？` | 列出已展示范围内的费用项（凭证号+摘要+金额）；截断部分应说明"未能完整展示"，**不得**补全没见过的开支 |
| 3.4 | 接 3.3，`其中宽带费那笔多少钱？` | 给出与 3.3 一致的具体金额；若 3.3 未展示到，应诚实说"未见，可翻页确认"，**不得**现编金额 |
| 3.5 | `幻晟的科目体系大概有哪些一级科目？` | 列出真实科目（1001 库存现金、1002/100201 银行存款、1122 应收账款等）；数据被截断时如实说明 |
| 3.6 | 接 3.2，`刚才说的销项税是哪张凭证、多少钱？` | 复述与 3.2 一致（记-001 / 298.01 或届时真实值），体现跨轮一致 |

## 6. 稳定性与异常路径（P1）

| # | 操作 | 预期 |
|---|---|---|
| 6.1 | 同一问题换 3 种问法各发一次（如 3.3 的三种变体） | 至少 2 次给出合格回答；失败那次的回复应为礼貌降级话术，而非错误堆栈/JSON |

| 6.4 | 观察 3.x 各回合的进度提示 | 每步有进度文案（"正在搜索账套…"等），文案不含查询结果 |

## 8. 失败排查指引

1. **回复"查询失败/请稍后再试"** → `grep fallback_reply /tmp/fshine-server.log`
   - `turn_timeout`：回合超 150s（多为上游慢或模型重试过多），重发一般恢复
   - `no_tool_for_live_data`：模型没调工具（已有强制重查一轮，二次出现才异常）
   - 无日志却降级：多为上游浏览器失败，`grep "17dz-mcp" /tmp/fshine-server.log | tail` 看 Page crashed / NEEDS_LOGIN
2. **回复"系统登录需要处理"** → 自动登录自愈失败，检查凭据（`.env` 的 DZ_PHONE、`~/.config/17dz/password`）；手动兜底：`cd ~/projects/17dz-platform && ./src/lib/scripts/login.sh`
3. **怀疑回答编造** → 直接探针原始数据核对：
   `cd ~/projects/17dz-platform && printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"p","version":"0"}}}' '{"jsonrpc":"2.0","method":"notifications/initialized"}' '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"list_vouchers","arguments":{"accountSetId":"as_001","period":"202608"}}}' | npm run --silent mcp`
4. **审计追溯** → `sqlite3 data/agent.db "SELECT tool_name,status,source,trace_id,error_code FROM tool_calls ORDER BY id DESC LIMIT 20;"`
5. **重启 server** → `pkill -f "apps/server/main.ts"; nohup npm start > /tmp/fshine-server.log 2>&1 &`

## 10. 真实 E2E 回归（AI 主执行，企微抽样）

真实 E2E 默认由 AI 直接向 Agent 消息入口发送数据；不要求经过企业微信。
企业微信只做可选的渠道抽样，用于验证真实通道收发和渲染，不作为功能验收前置条件。

### 10.1 AI 入口（主验收入口）

AI 入口调用与企微相同的 Agent 消息处理链，只替换消息来源，不得绕过 Agent 直接调用 17dz 页面或数据库。
实现上可以使用现有消息处理 API/CLI；如果尚未提供独立 CLI，则由验收执行器直接注入同样的消息对象。验收不需要启动企微连接：

```json
{
  "wecomUserId": "真实用户 ID",
  "conversationId": "real-e2e-20260917",
  "messageId": "e2e-msg-001",
  "chatType": "single",
  "text": "幻辰的应收账款还有多少",
  "receivedAt": "2026-09-17T00:00:00.000Z"
}
```

同一场景的追问复用 `conversationId`，每条消息必须有新的 `messageId`。AI 回归必须记录 `requestId`、工具调用、参数、状态、traceId 和最终回复。

### 10.2 读场景

涉及账套、科目或客户简称时，必须先通过对应的模糊解析接口取得稳定 ID；
只有唯一匹配后才能调用余额/明细接口。出现 `ambiguous` 必须让用户选择，
`not_found` 与 `unavailable` 必须如实说明，禁止猜 ID 或退回凭证净发生额推算。

| 用例 | 输入 | 必须核验 |
|---|---|---|
| R1 | `帮我查一下幻辰的应收账款还有多少` | 先搜索账套并唯一确定 `as_003`，再以 `search_references(referenceType="subject", query="应收账款")` 解析科目（核对 `1122`），随后按工具返回期间调用 `get_subject_balance(accountSetId, subjectCode="1122", period)`；返回期末余额和来源；不得用凭证净发生额代替余额 |
| R2 | `幻东机械在幻辰账套还欠多少？` | 先调用 `search_references(referenceType="assistant", filters.subjectCode="1122")` 解析客户；唯一匹配后用返回的 `assistantId` 调用 `get_auxiliary_balance(accountSetId, subjectCode="1122", period, assistantId)`；客户、账套、期间、期末余额可复核 |
| R3 | `幻辰 2026 年 8 月应收账款发生了哪些变化？` | 可以调用凭证/明细事件工具；回复必须标明“发生额”，不能说成期末余额 |
| R4 | `列出幻辰 2026 年 8 月的凭证` → `下一页` | cursor 原样续用；不重复、不编造；说明展示范围 |
| R5 | `幻晟的科目体系大概有哪些一级科目？` | 基于当前账套查询结果回答；不能把历史缓存当当前事实 |
| R6 | 读取 voucher 域知识资源 | 只能读取 MCP 声明且 Host allowlist 放行的资源；禁止读取 auth、selector、执行源码和任意路径 |

### 10.3 写接口前置回归（禁止提交）

AI 可以测试写接口的校验、预览和 Workflow 状态，但默认禁止调用：

```text
submit_voucher
submit_voucher_batch
workflow.confirm
```

| 用例 | 输入 | 必须核验 |
|---|---|---|
| W1 | 合法汇票契约，调用 `validate_voucher` | 借贷平衡、结构合法；不产生凭证号或 docId |
| W2 | 借方 100、贷方 80 的契约 | 返回 `CONTRACT_INVALID` 或等价借贷不平错误 |
| W3 | `workflow.start(voucher.bill_batch)` | 进入 `needs_input` 或 `ready_for_confirmation`；返回 NEEDS/预览；不执行保存 |
| W4 | 同一 Workflow 重复使用 idempotencyKey | 返回同一 taskId，不重复预检或执行 |
| W5 | 重启 MCP 后调用 `workflow.status(taskId)` | status、revision、needs、preview、input 和幂等关系保持 |

### 10.4 企业微信抽样

本节为可选项，不影响 AI 主验收结论。

AI 回归通过后，人工抽样发送：

1. `幻辰的应收账款还有多少`
2. `幻东机械在幻辰账套还欠多少？`
3. `列出幻辰 2026 年 8 月的凭证`，随后 `下一页`
4. 合法凭证“先校验和预览，不要提交”

人工抽样重点看：回复完整、账套和期间正确、来源显示、Markdown 正常渲染、无内部 JSON/trace、无未授权数据。

### 10.5 人工验收范围

功能验收不要求人工逐项执行。若需要人工复核，直接向 Agent 发送以下三组消息即可：

1. `帮我查一下幻辰的应收账款还有多少`，确认先解析账套/科目，再返回余额表期末余额。
2. `幻东机械在幻辰账套还欠多少？`，确认使用唯一 `assistantId` 查询辅助余额；若简称有多个候选，应先让用户选择。
3. `列出幻辰 2026 年 8 月的凭证`，随后发送 `下一页`，确认游标续接且不重复。

写接口只验校验、预览和 Workflow 状态，不执行提交或确认。
