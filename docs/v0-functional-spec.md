# fshine-agent 功能规格

状态：当前实现基线

架构：[`v0-architecture.md`](v0-architecture.md)

## 1. 用户与价值

用户是使用企微机器人的内部员工。Main Agent 是**编排者**：负责对话、长任务拆解和信息补齐，不拥有业务口径。涉及执行层实时数据时由宿主委派给执行层子 Agent；子 Agent 的自然语言结果**直接作为本轮回复**，不经 Main Agent 改写——因此它没有机会拿旧答案收尾。

## 2. 执行层须声明的能力面

执行层经声明面接入，通过 operation 清单声明可执行的能力。通用层不预置任何业务能力；以下为执行层声明示例，具体能力由接入的执行层自己定义：

| 声明字段 | 说明 |
|---|---|
| `name` | 操作标识（如 `finance.query-receivables`） |
| `domain` | 业务域（如 `finance`、`voucher`） |
| `command` | 执行命令或脚本路径 |
| `access` | 访问级别（`read` / `write` / `admin`） |
| `effects` | 副作用声明（`none` / `read` / `write` / `external`） |
| `executor` | 执行器类型（`mock` / `real` / `script`） |
| `est_seconds` | 预估执行时间（秒） |
| `weight` | 计划重量（影响计划门判定） |
| `args` | 参数声明（名称、类型、必填、枚举值） |
| `serve` | 服务矩阵（哪些 profile / 环境下可用） |
| `protocol` | 协议版本（如 `a2a-1`） |
| `label` | 用户可见标签 |

> 权威来源：`docs/execution-layer-admission.md` 的 A1–A14 准入表。

## 3. 范围外能力

```text
通用多 Agent 编排和跨领域结果聚合
知识库/RAG、自动学习和主动巡检
面向外部客户的渠道
完整 RBAC、审批流、长任务调度和浏览器人工接管
```

## 4. 核心流程

### 4.1 查询请求

```text
员工："查一下应收余额。"
  -> Main Agent 申报本轮需要委派，并加工请求（补上指代解析出的实体）
  -> 宿主用当前消息委派
  -> 执行层子 Agent 读取 Skill、提交计划、执行领域脚本
  -> 计划门按重量决定 直接执行 / 通知后执行 / 等用户确认 / 停止
  -> 子 Agent 的自然语言结果直接回复用户（含实体、期间、来源）
```

Main Agent 不得凭历史上下文猜实体 ID、期间、金额或状态。结果不完整时必须如实说明，并可把用户的“下一页/继续”作为同一任务的补充请求。

### 4.2 实体不唯一

子 Agent 或 Main Agent 发现多个候选时，向用户列出可见候选并请求选择；不得猜测。用户选择后，Main Agent 携带同一 `taskId` 继续任务。

### 4.3 需要补充信息

子 Agent 可以直接返回自然语言问题。Main Agent 决定原样转达、补充上下文后重试，或结束当前对话。代码不通过关键字正则推断 `needs_input`、`preview` 或 `blocked` 等状态。

### 4.4 无权限或上游不可用

```text
用户请求未授权实体
  -> 领域脚本/平台能力拒绝
  -> Main Agent 说明无权访问，不泄露其他实体信息

执行层登录失效或脚本失败
  -> 子 Agent 如实返回失败原因
  -> Main Agent 给出简洁降级说明
```

## 5. 功能规则

- 每个企微请求都有 `requestId`；每个委派任务都有绑定当前主会话和 principal 的 `taskId`。
- 涉及执行层实时数据时必须产生本轮真实执行（激活计划 + 至少一次执行层调用），不得用模型记忆或历史回答代替查询。宿主在出口强制这条：没有执行凭证就不外发含数字结论的回复。
- 子 Agent 返回自然语言，直接展示给用户。代码不包装领域流程状态，也不用正则猜测子 Agent 状态。
- 执行面扩大（更多实体 / 更长期间 / 更高耗时）时，用户先看到范围和预计耗时；超过更高门槛必须等用户真实回复。
- 数据回复应说明使用的实体、期间和数据范围；不确定或未取得的信息必须明确标注。
- 用户可见错误不得包含堆栈、绝对路径、凭据、内部提示词或其他未授权数据。
- 所有子 Agent 会话和任务都必须在超时、取消或完成后释放运行资源。

## 6. 必要配置

```yaml
principals:
  wecom:<user-id>:
    accountSetScope: all
    enabled: true

contextProfiles:
  <profileId>:
    root: /path/to/execution-layer
    # 每个 profile 声明自己的网关调用形式（相对 root，宿主 spawn 用它，不硬编码）。
    gateway: bin/<gateway-name>
    # 运行态技能面：只认平台仓声明的技能目录。
    skillRoots: [".agents/skills-serve"]
    # 执行层称谓(可选,≤32 字符无控制字符):进 Main Agent 系统提示词的委派句。
    # 缺省 = 宿主中性缺省「执行层子 Agent」。
    # executorLabel: <执行层自定称谓>
    # 委派工具名(可选,≤48 字符,小写字母开头仅小写字母/数字/下划线):模型可见协议面。
    # 缺省 = 宿主中性缺省 delegation_task。
    # toolName: <执行层自定工具名>
    # Worker 单次任务预算(可选，默认 10 分钟)
    workerTimeoutMs: 600000
```

`root` 必须是部署时确定的工作目录；`gateway` 和 `skillRoots` 只能指向 root 内的相对路径。模型和用户不能通过消息覆盖这些配置。

会话键为 `wecomUserId + conversationId`。服务目前以同步回复为主，具体渠道和子 Agent 超时以运行配置为准。

## 7. 验收标准

1. 启用的用户可以通过企微查询授权实体并得到真实结果。
2. 涉及实时数据的请求都会产生本轮执行层执行，而不是编造或重放答案。
3. 子 Agent 在正确的执行层工作目录加载 Skills；不会使用用户提供的任意 cwd。
4. 多候选实体会请求澄清，不会猜测。
5. 用户补充信息后可以使用原 task ID 继续，且其他用户不能接管该任务。
6. 子 Agent 的追问会被 Main Agent 以自然语言转达，普通成功结果也直接转成自然语言回答。
7. 登录失效、脚本错误、空结果、超时和取消都有安全降级行为。
8. 只读场景不会调用写操作；写操作如未来启用，必须由领域脚本实施确认和幂等硬闸。
9. 审计能从企微消息关联到主会话、taskId 和最终回复，不泄露秘密。

## 8. 交付顺序

```text
1. Main Agent 编排与 Pi driver
2. 委派工具及任务持久化/会话恢复
3. 执行层工作目录与 Skills 路径校验
4. 领域脚本真实查询与子 Agent 提示
5. 企微 channel 联调
6. AI 入口与企微抽样验收
```
