# 表格验收判定口径

适用于在交付一张表格前判断它是否正确。本文只讲**判定口径**——什么算通过、证据从哪来、分几档、实算结果怎么读、不过会怎样。不涉及任何具体平台、工具、命令、参数或字段语法。

## 1. 什么算验收通过

- **全量对平，不抽样豁免**：对平是对整张表、全部相关行与列而言的；不能因为抽了几行一致就宣布整张表通过，也不能声明某部分「不参与对账」来回避差异。
- **金额精确到分**：金额一致性以分为最小单位判断，四舍五入到元或到角的「大致相等」不算通过。
- **对不上如实报差异，不调宽判据**：出现差异就是差异，不能用放宽容差、改变口径、换快照、挑子集等办法把差异「对平」。判据在验收前定好，验收中不得为了通过而改动。
- **不强行配平**：算不平就停下，把差异摆出来，不自行调整某个数把合计凑平。

## 2. 证据从哪来（oracle 优先级）

判断一张表是否对平，证据有强弱之分，按下面的优先级取用：

1. **文件自带的对账列**最优先：若表内已有对账列、差异列、核对列等专门用来对账的字段，先以它为准。
2. **总额对平**其次：没有对账列时，用各行合计与总额（或交叉来源的合计）是否一致来判定。
3. **抽样只供用户复核**，不构成验收证据：抽样一致不能推出整表通过，抽样发现的问题可以作为待确认线索，但「抽样没问题」不是通过结论。

证据不足以下结论时，如实说证据不足，不用低优先级证据冒充高优先级结论。

## 3. 两档判定

按表格里有没有公式分两档，判定方式不同：

- **纯数据表格**（全是写死的值，没有公式）：按第 1 节的口径直接断言——逐项/合计对平即通过，对不平即差异。
- **带公式的表格**：不能只看表里现成显示的值，必须**实算**后再判定。现成显示的值可能是旧缓存，不代表公式的当前真实结果；只有实算后的计算值才作判据。
- **外部来源的表格**一律**按带公式档对待**：即使当前读到的格子里没有公式，也先当作需要实算处理，不因「看起来是纯数据」就降到纯数据档。

分档只看「是否可能含公式/是否外部来源」，不看表面显示值。

## 4. 解读实算结果

实算会给出一份结果，读它时遵守下面几条：

- **实算结果里有值差异，不等于你写错了**：差异常来自共享公式与静态值混排——同一批汇总格里有的格是公式、有的格是人工写死的数，实算后公式格变了、写死的格没变，于是出现差异。这是表格本身的构成事实，不是「算错了」的证据；要定位差异来源，不要直接归咎于操作失误。
- **公式格取计算值**：判断公式格对不对、拿它去合计或比对时，一律用实算后的计算值，不用格子里存的旧缓存值。
- **空不等于 0**：空格与数值 0 是两种不同状态，不能把空白当成 0 参与合计，也不能把 0 当成空略过。
- **文本型数字**：看起来是数字、实际以文本存放的值，不能想当然当作数值参与计算；先确认它的类型与口径，再决定如何处理，不要静默把它算进去或丢掉。

## 5. 交付纪律

- **带公式的表格不过实算就不投递**：带公式（以及外部来源）的表格，只有在实算完成且按上述口径判定通过后才交付；实算缺失、实算结果为 fail、或实算对象与待交付文件对不上，都不交付，并如实说明原因。
- **纯数据表格与纯数据导出**不受实算约束，按第 1 节口径判定后照常交付。
- 不管哪一档，对不平时都如实报告差异，不带病交付。
